# agent-starter-kit

Универсальная настройка кодинг-агента (Claude Code) для нового проекта: правила, навыки, hooks, права и память между сессиями. Не привязана к стеку: стек выясняется опросом при старте проекта.

## Быстрый старт

1. Скопируй содержимое папки в корень нового проекта (включая скрытые файлы):
   ```
   cp -R agent-starter-kit/. /путь/к/новому-проекту/
   rm /путь/к/новому-проекту/README.md   # этот README нужен только в шаблоне
   ```
   Или на GitHub нажми «Use this template», если репозиторий отмечен как Template.
2. Открой проект в Claude Code. Агент увидит в `CLAUDE.md` указание провести опрос и запустит навык `new-project-interview`.
3. Ответь на вопросы (проект, функции, стек, запуск, секреты, качество, процесс, защита). Подтверди итог.
4. Агент заполнит `docs/spec.md`, `docs/plan.md`, `AGENTS.md`, права и проверки под твой стек.
5. Перезапусти сессию: hooks и настройки читаются при старте.

## Что внутри

| Файл | Зачем |
|---|---|
| `CLAUDE.md` | Указание провести опрос на новом проекте; подключает `plan.md` и `memory.md` в каждую сессию |
| `AGENTS.md` | Шаблон паспорта проекта (стек, команды, правила, запреты). Общий формат, его читают и другие агенты |
| `.claude/settings.json` | Права (git-команды разрешены, push спрашивает, чтение `.env` и опасные команды запрещены) и подключение hooks |
| `.claude/hooks/block_protected.py` | Блокирует правку `.env*`, `.git/`, lock-файлов через Edit/Write |
| `.claude/hooks/block_bash_writes.py` | То же для команд Bash (redirect, `sed -i`, `rm`, `git config` и т. п.); эвристика, не песочница |
| `.claude/hooks/check_after_edit.py` | После правки проверяет файл. Встроено: `.json`, `.js`, `.py`. Свои проверки: словарь `PROJECT_CHECKS` в начале файла |
| `.claude/hooks/test_block_bash_writes.py` | Юнит-тесты для hook-а Bash: `python3 .claude/hooks/test_block_bash_writes.py` |
| `.claude/rules/run-tests-before-done.md` | Не называть фичу готовой, пока не пройдены тесты (глобальное) |
| `.claude/rules/session-memory.md` | Как вести `docs/memory.md` и архив (глобальное) |
| `.claude/rules/tdd.md`, `tests.md` | TDD и правила тестов; подгружаются по `paths`, поправь под структуру проекта |
| `.claude/skills/new-project-interview` | Опрос «grill me» при старте проекта |
| `.claude/skills/write-tests` | Процедура написания юнит-тестов до кода |
| `.claude/skills/review-step` | Ручная проверка шага перед слиянием: `/review-step <шаг>` |
| `docs/plan.md`, `docs/memory.md` | Шаблоны плана и журнала |

## Как работает память

- `docs/memory.md` держит не больше двух записей плюс «Постоянные ловушки»; подключён в контекст каждой сессии.
- Старые записи уходят в `docs/memory-archive-<дата>-<n>.md` (не больше 200 строк в файле, при превышении новый файл). Архив в контекст не подключён.
- Запись пишет агент в конце сессии или шага по правилу `session-memory.md`.

## Что не переносить в этот репозиторий

- `.claude/settings.local.json`, `.env*`: личное и секреты (они в `.gitignore`).
- Журнал и архив конкретного проекта.

## Ограничения

- Hooks, `settings.json`, skills и `rules/` работают только в Claude Code. Другие агенты прочитают лишь `AGENTS.md`, поэтому общие правила держи там.
- Hook `block_bash_writes.py` блокирует любую команду Bash, в тексте которой встречается имя файла секретов, даже в heredoc. Такой текст пиши инструментом Write/Edit.
- Проверено на Claude Code версии, с которой создавалась настройка; при крупных обновлениях проверь формат hooks в `settings.json`.

## Чек-лист нового проекта

- [ ] Скопирован шаблон, удалён этот README
- [ ] Пройден опрос, есть `docs/spec.md` и заполненный `AGENTS.md`
- [ ] В `PROJECT_CHECKS` добавлены проверки стека
- [ ] В `settings.json` разрешены команды сборки и тестов
- [ ] `paths` в `tdd.md` и `tests.md` совпадают с реальными папками
- [ ] Сессия перезапущена, `git init` и первый коммит сделаны по твоей просьбе
