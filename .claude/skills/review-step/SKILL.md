# review-step

Проверь изменения текущей ветки относительно основной ветки на соответствие шагу плана: $ARGUMENTS

Если аргумент не указан, определи шаг по изменениям и назови его в начале отчёта.

## Порядок

1. Прочитай `docs/spec.md` (требования шага, технические и нефункциональные требования, «Вне рамок») и `docs/plan.md`.
2. Посмотри изменения: `git diff <основная-ветка>...HEAD` и `git log <основная-ветка>..HEAD`. Имя основной ветки возьми из `AGENTS.md`.
3. Запусти юнит-тесты (команда в `AGENTS.md`). Если команда ещё TODO, так и напиши, не выдумывай.
4. Проверь по списку ниже и выдай отчёт.

## Чек-лист

- **Соответствие спецификации**: требование шага реализовано целиком; нет функциональности из раздела «Вне рамок».
- **Секреты**: ключи, токены и пароли не попали в код, конфиги и историю коммитов.
- **TDD**: у нового поведения есть тесты, тесты проходят, их не ослабляли ради прохождения.
- **Устойчивость**: сбой внешнего сервиса не теряет данные пользователя.
- **Стек**: нет новых зависимостей и технологий вне спецификации без согласования.

## Формат отчёта

Три раздела: «Блокирует слияние», «Стоит исправить», «Замечания». Для каждого пункта: файл и строка, суть, как исправить. Если проблем нет, напиши это прямо. Ничего не исправляй сам, только сообщай.
